# Автоматизация SberBrowser с подробным логом

## Язык общения

Общайся с пользователем **по-русски**: пояснения, статусы, вопросы, итог.
Технические команды, селекторы, пути и имена флагов остаются как есть.

## Назначение

Выполняй последовательности действий в **SberBrowser** (браузер на Chromium):
переходы по сайтам, вход под уже имеющейся сессией пользователя, клики, ввод в
формы, скачивание файлов, извлечение данных. Подключение идёт к **уже открытому**
браузеру по Chrome DevTools Protocol (CDP), поэтому все логины и куки на месте —
это важно для внутренних порталов.

Ты пишешь сценарий **кодом** под конкретную задачу, но не с нуля: используешь
поставляемый драйвер `scripts/sber_driver.py`. Он даёт готовые действия (`goto`,
`click`, `fill`, `download`, …) и — главное — **сам пишет подробный лог каждого
шага**. Если что-то ломается, пользователь пришлёт папку прогона, а по ней видно,
на каком шаге, с каким селектором и почему упало: с точным сообщением, скриншотом
и снимком DOM. Не пиши автоматизацию на «голом» Playwright в обход драйвера —
потеряешь именно эту диагностику.

## Перед началом

1. Определи абсолютный путь к каталогу навыка (где `SKILL.md`) — далее `$SKILL_ROOT`.
2. Убедись, что установлен `playwright` (`pip install playwright`). Отдельный
   Chromium качать **не нужно** — используется тот, к которому подключаемся, а
   `playwright install` в этой среде не запускай.

## Обязательный процесс

### 1. Подключись к SberBrowser по CDP

Автоматизация работает только с браузером, запущенным в режиме отладки. Проверь
подключение до всего остального:

```bash
python3 "$SKILL_ROOT/scripts/run_flow.py" connect-check
```

Если `ready: true` — покажет открытые вкладки, можно работать. Если нет — команда
выведет `hint` с точной командой запуска. Передай её пользователю: нужно закрыть
SberBrowser и запустить его с `--remote-debugging-port=9222` и отдельным профилем,
затем один раз залогиниться на нужных сайтах. Порт можно переопределить флагом
`--cdp` (или переменной `SBER_CDP_URL`). Подробности и путь к бинарю на macOS — в
`references/setup-cdp.md`.

Не начинай писать сценарий, пока `connect-check` не прошёл: без подключения любой
прогон сразу упадёт.

### 2. Разберись со страницей, прежде чем писать шаги

Селекторы — источник большинства поломок. Не угадывай их. Если структура сайта
неизвестна, начни с короткого разведочного сценария: `goto` на нужную страницу и
`screenshot`, затем посмотри снимок и, при необходимости, DOM. Строй селекторы от
устойчивого к хрупкому: `id` и `name` → атрибуты (`[data-test=...]`,
`[aria-label=...]`) → текст (`text=Скачать`) → в последнюю очередь длинные
CSS-цепочки, которые ломаются от любой перерисовки.

### 3. Напиши сценарий

Сценарий — это python-файл с функцией `run(s)`, где `s` — сессия драйвера.
Заготовку можно создать командой:

```bash
python3 "$SKILL_ROOT/scripts/run_flow.py" new-flow flow.py
```

Доступные действия (все логируются сами) перечислены в шапке заготовки и в
`references/driver-api.md`. Ключевое:

```python
def run(s):
    s.goto("https://internal.example/reports")
    s.wait_for("#search")                       # дождись, не кликай вслепую
    s.fill("#search", "квартальный")
    s.click("button[type=submit]")
    s.wait_for("table.results")
    path = s.download("a.export-xlsx", save_as="report.xlsx")
```

Правила, которые экономят часы отладки:

- **Жди явно.** Перед действием над элементом делай `wait_for` — не полагайся на
  то, что страница уже отрисовалась. Большинство таймаутов — это «кликнул раньше,
  чем элемент появился».
- **Пиши маленькими шагами.** Один `click`/`fill` на строку. Дробные шаги дают
  дробный лог: сразу видно, где именно сломалось.
- **Скачивание — через `s.download(...)`**, а не ручной клик: драйвер дождётся
  файла, сохранит его и запишет путь и размер.
- **Не логируй секреты.** Значения `fill`/`type` в лог по умолчанию не пишутся
  (только длина) — так и оставь; флаг `--show-values` включай лишь по явной
  просьбе.

### 4. Запусти под логированием

```bash
python3 "$SKILL_ROOT/scripts/run_flow.py" run flow.py --out runs
```

Полезные флаги: `--cdp` (адрес CDP), `--timeout` (мс, по умолчанию 15000),
`--context` (индекс окна, если открыто несколько), `--download-dir` (куда
складывать файлы), `--shots` (скриншот на каждом шаге, для разведки),
`--show-values` (писать вводимый текст — осторожно).

Каждый прогон создаёт папку `runs/<время>/` с логами и отчётом. Код выхода `0` и
`"status": "ok"` — успех; иначе смотри `report.md`.

### 5. Разбери результат

Открой `report.md` из папки прогона. При успехе — сверь, что скачались нужные
файлы (раздел «Скачано файлов») и итоговый URL верный. При сбое — раздел «Что
упало» называет шаг, ошибку, скриншот, снимок DOM и **вероятную причину**. Частые
случаи и что делать — в `references/debugging.md`.

Правь сценарий и запускай снова: обычно ломается селектор (сверь со снимком DOM),
не хватает `wait_for`, или требуется вход, которого нет в текущей сессии.

### 6. Заверши ответ

Дай пользователю: путь к папке прогона, статус, что скачалось, и — если сбой —
на каком шаге и почему, одной фразой. Если нужна твоя помощь в разборе, прямо
попроси прислать папку прогона (или хотя бы `report.md`, `run.log`,
`events.jsonl`, `console.jsonl` и скриншоты).

## Границы и честность

- **Куки и логины — пользователя.** Драйвер подключается к его браузеру и
  действует от его имени. Не выполняй действий, которых пользователь не просил,
  и не трогай ничего за пределами сценария.
- **Логи могут содержать чувствительное.** Скриншоты и снимки DOM показывают
  содержимое внутренних страниц. Прежде чем куда-то отправлять папку прогона,
  напомни пользователю просмотреть её. Пароли в лог не попадают (значения ввода
  скрыты), но экран — да.
- **Капча и 2FA не автоматизируются.** Если сценарий упёрся в них — остановись и
  попроси пользователя пройти их вручную в том же окне, затем продолжи.
- **Драйвер не закрывает браузер пользователя** — только своё соединение.

## Когда остановиться без результата

Остановись и назови причину, если `connect-check` не проходит (браузер не в
режиме отладки), нужен вход/капча, которых нет в сессии, или сценарий падает на
одном и том же шаге и снимок DOM показывает, что нужного элемента на странице
просто нет. Пустой или наугад собранный сценарий хуже честного «нужен доступ / не
тот селектор».

## Типичные ошибки

| Ошибка | Правильное действие |
|---|---|
| Писать на «голом» Playwright | Использовать `sber_driver` — иначе нет лога для разбора |
| Кликать, не дождавшись элемента | `wait_for` перед действием |
| Угадывать селекторы | Разведать: `screenshot`/DOM, строить от `id` к тексту |
| Ручной клик по ссылке для скачивания | `s.download(...)` — дождётся и сохранит файл |
| Начать без `connect-check` | Сперва убедиться, что CDP подключается |
| Писать пароли в лог | Оставить значения ввода скрытыми (без `--show-values`) |
| Пытаться обойти капчу/2FA кодом | Попросить пользователя пройти вручную в том же окне |
