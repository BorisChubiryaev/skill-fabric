# Разбор прогонов: что искать в логах

Справочник для агента (и для автора навыка, когда пользователь присылает папку
прогона). Цель — по логам понять, на каком шаге и почему сломалось, не видя
экрана.

## Что лежит в папке прогона

```
runs/<время>/
├── report.md        ← начните отсюда: итог, что упало, вероятная причина
├── summary.json     статус, счётчики, список скачанного, финальный URL
├── run.log          человекочитаемая лента шагов с временами
├── events.jsonl     по событию на шаг: action, target, url, ok, ms, error, screenshot
├── console.jsonl    сообщения консоли браузера и ошибки страницы
├── network.jsonl    только неуспехи: битые запросы и HTTP ≥ 400
├── screenshots/     скриншоты (падения — с суффиксом FAIL)
├── dom/             снимки DOM на момент падения
└── downloads/       скачанные файлы
```

Порядок чтения: `report.md` → скриншот упавшего шага → снимок DOM (есть ли нужный
элемент вообще) → `console.jsonl` и `network.jsonl`, если дело не в селекторе.

## Таблица типовых причин

| Что в логе | Что произошло | Что делать |
|---|---|---|
| `TimeoutError` на `click`/`fill`/`wait_for` | Элемент не появился вовремя | Сверить селектор со снимком DOM; добавить `wait_for`; поднять `timeout_ms` |
| `TimeoutError` на `goto` | Страница не открылась | Проверить URL, доступ, VPN/прокси |
| `download`: таймаут | Скачивание не началось | Тот ли элемент; не открылся ли файл во вкладке; нет ли подтверждения |
| `not attached` / `detached` | Элемент исчез (страница перерисовалась) | `wait_for` нужного состояния перед действием |
| `net::ERR_...` в network.jsonl | Сетевая ошибка запроса | Доступность ресурса, сертификаты, прокси |
| HTTP 401/403 | Не авторизованы | Нужен вход в этой сессии; проверить, тот ли профиль/окно |
| Пустая страница, в DOM форма логина | Сессия не залогинена | Пользователю войти в окне автоматизации и повторить |
| `console.jsonl` полон ошибок JS | Страница сама сломалась/не догрузилась | Дать ей время; проверить, не блокирует ли что-то расширение/прокси |

## Селектор или ожидание?

Это первый вопрос при таймауте. Откройте снимок DOM упавшего шага и поищите
элемент:

- **элемента нет вовсе** → селектор неверный, либо вы не на той странице (сверьте
  `url` шага в `events.jsonl`), либо нужен вход;
- **элемент есть** → он появился позже действия: добавьте `wait_for` перед шагом
  или увеличьте таймаут точечно;
- **элемент есть, но другой** (совпало несколько) → уточните селектор, добавьте
  контейнер или используйте `text=`.

## Признаки, что нужен человек

- в DOM/скриншоте — форма входа, СМС-код, капча;
- HTTP 401/403 на защищённых страницах;
- редирект на страницу авторизации (виден в `url_after` события).

В этих случаях сценарий не «чинится» кодом: пользователь проходит вход/капчу
вручную в том же окне (сессия сохранится), после чего сценарий запускается снова.

## Как просить лог у пользователя

Достаточно папки прогона целиком. Если она большая или содержит чувствительное —
попросите хотя бы `report.md`, `run.log`, `events.jsonl`, `console.jsonl` и
скриншот упавшего шага. Напомните, что скриншоты и снимки DOM показывают
содержимое страниц — пусть пользователь просмотрит их перед отправкой.
