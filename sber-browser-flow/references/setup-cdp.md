# Подключение к SberBrowser по CDP

Справочник для агента и пользователя. Автоматизация работает только с браузером,
запущенным в режиме отладки (Chrome DevTools Protocol). Читай, если
`connect-check` не проходит.

## Зачем именно так

Мы подключаемся к **уже открытому** SberBrowser, а не запускаем чистый Chromium.
Это сохраняет сессию пользователя: куки, вход на внутренние порталы, доменную
авторизацию. Ценой одного условия — браузер должен быть запущен с флагом отладки.

## Запуск SberBrowser в режиме отладки (macOS)

Закройте все окна SberBrowser, затем запустите из терминала:

```bash
/Applications/SberBrowser.app/Contents/MacOS/SberBrowser \
  --remote-debugging-port=9222 \
  --user-data-dir="$HOME/.sber-automation-profile"
```

- `--remote-debugging-port=9222` — включает CDP на порту 9222.
- `--user-data-dir=...` — **отдельный** профиль для автоматизации. Так вы не
  трогаете основной профиль, а сессия автоматизации сохраняется между запусками.
  В этом окне один раз залогиньтесь на нужных сайтах — дальше вход будет помнить.

Точный путь к бинарю может отличаться. Если файла нет, найдите его:

```bash
ls /Applications | grep -i sber          # имя .app
ls "/Applications/SberBrowser.app/Contents/MacOS"   # имя бинаря внутри
```

Иногда бинарь называется иначе (латиницей/с суффиксом) — используйте то, что
реально лежит в `Contents/MacOS`.

## Проверка

```bash
python3 scripts/run_flow.py connect-check
```

- `ready: true` и список вкладок — всё готово.
- ошибка — браузер не запущен в режиме отладки, либо занят другой порт. Проверьте
  вручную: `curl http://localhost:9222/json/version` должен вернуть JSON с полем
  `Browser`.

## Другой порт или адрес

Если порт 9222 занят, запустите браузер с другим (`--remote-debugging-port=9333`)
и укажите его при запуске:

```bash
python3 scripts/run_flow.py run flow.py --cdp http://localhost:9333
# либо разово через переменную окружения
SBER_CDP_URL=http://localhost:9333 python3 scripts/run_flow.py connect-check
```

## Несколько окон

Если в браузере открыто несколько окон (контекстов), драйвер по умолчанию берёт
первое. Нужное окно выбирается флагом `--context <индекс>` (0, 1, …). В `run.log`
в начале прогона печатается число контекстов и стартовый URL — по ним видно,
туда ли подключились.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `нет ответа по CDP` | Браузер запущен без `--remote-debugging-port`. Перезапустите с флагом. |
| Подключается, но не то окно | Несколько контекстов — укажите `--context`. |
| Логины слетают между запусками | Не задан постоянный `--user-data-dir`. Используйте один и тот же каталог профиля. |
| Порт занят | Другой процесс держит 9222 — выберите иной порт и передайте через `--cdp`. |

## Безопасность

Режим отладки открывает локальный порт, через который можно управлять браузером.
Держите его на `localhost`, не пробрасывайте наружу и закрывайте окно
автоматизации, когда закончили. Действия выполняются от имени пользователя в его
сессии — запускайте только те сценарии, которым доверяете.
