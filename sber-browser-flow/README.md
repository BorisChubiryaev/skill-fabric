# Автоматизация SberBrowser с логами

Навык для кодинг-агента (GigaCode Desktop, Claude Code и совместимых): выполняет
последовательности действий в **SberBrowser** (браузер на Chromium) — заходит на
сайты под уже имеющейся сессией пользователя, кликает, заполняет формы, скачивает
файлы и извлекает данные. Агент пишет сценарий кодом под конкретную задачу,
используя поставляемый драйвер, который **логирует каждый шаг** — чтобы по
присланному логу можно было понять, что сработало, а что нет.

## Как это устроено

- **Подключение по CDP** к уже открытому SberBrowser: сохраняются логины и куки,
  что важно для внутренних порталов.
- **Агент пишет `run(s)`** — короткий python-сценарий поверх драйвера
  `sber_driver`. Действия читаются как список шагов: `goto`, `wait_for`, `fill`,
  `click`, `download`, `extract`.
- **Каждый прогон пишет папку с логами**: человекочитаемый `run.log`,
  структурированный `events.jsonl`, консоль браузера, сетевые ошибки, скриншоты и
  снимки DOM на падении, и `report.md` с вероятной причиной сбоя.

## Что внутри лога прогона

```
runs/<время>/
├── report.md      итог + что упало + вероятная причина  ← это присылать автору
├── summary.json   статус, счётчики, скачанные файлы
├── run.log        лента шагов с временами
├── events.jsonl   по событию на шаг
├── console.jsonl  консоль браузера и ошибки страницы
├── network.jsonl  битые запросы и HTTP ≥ 400
├── screenshots/   скриншоты (падения — с суффиксом FAIL)
├── dom/           снимки DOM на падении
└── downloads/     скачанные файлы
```

## Требования

- кодинг-агент с доступом к файлам и запуску команд;
- Python 3.11+ и `playwright` (`pip install playwright`) — **свой Chromium
  качать не нужно**, используется тот, к которому подключаемся;
- SberBrowser, запущенный в режиме отладки (см. `references/setup-cdp.md`).

Сеть при работе — только к тем сайтам, которые открывает сценарий.

## Установка из ZIP

```bash
unzip sber-browser-flow.zip -d ~/.agents/skills
```

Появится `~/.agents/skills/sber-browser-flow/`. Вместо `.agents/skills`
используйте каталог навыков вашего агента (например, `~/.gigacode/skills/`).

## Быстрый старт

```bash
S=scripts/run_flow.py
# 1. запустить SberBrowser в режиме отладки (см. references/setup-cdp.md), затем:
python3 $S connect-check
# 2. создать заготовку и отредактировать под задачу
python3 $S new-flow flow.py
# 3. запустить с логированием
python3 $S run flow.py --out runs
# 4. открыть runs/<время>/report.md
```

Пример готового сценария — в `examples/download_report.py`.

## Проверка инструмента

```bash
python3 -m unittest scripts/test_sber_flow.py -v
```

Тесты сами поднимают предустановленный Chromium с CDP и локальный сайт —
SberBrowser для проверки не нужен.

## Гарантии и ограничения

Драйвер подключается к браузеру пользователя и действует от его имени; он не
закрывает браузер и не делает ничего вне сценария. Значения ввода в лог не
пишутся (только длина), но скриншоты и снимки DOM показывают содержимое страниц —
просматривайте папку прогона перед отправкой. Капча и 2FA автоматизацией не
обходятся: их проходит пользователь вручную в том же окне.
