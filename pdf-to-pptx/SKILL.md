# Конвертация PDF в редактируемую PPTX

## Назначение

Собери из PDF настоящую редактируемую презентацию PowerPoint (`.pptx`): одна
страница PDF → один слайд. Текст переноси как настоящие текстовые поля (правится
в PowerPoint), картинки — как изображения, а графику сохраняй визуально. Исходный
PDF не меняй. Работай честно: где точность теряется — фиксируй это в отчёте, а не
выдавай приблизительный результат за идеальный.

Используй только поставляемый инструмент `scripts/pdf2pptx.py` (зависимости —
`pymupdf` и `python-pptx`). Не собирай PPTX вручную из XML и не пересохраняй через
сторонние конвертеры: это обходит проверки структуры и отчётности.

## Что реально достижимо (прочитай перед обещаниями пользователю)

PDF — формат фиксированной вёрстки (глифы по координатам, векторы, растры). В нём
нет понятий «текстовый блок», «список», «таблица», «слайд». PPTX — редактируемая
структура. Поэтому конвертация — это **реконструкция**, и качество всегда
балансирует между визуальной точностью и редактируемостью. Есть три режима:

| Режим | Визуальная точность | Что редактируется | Когда выбирать |
|---|---|---|---|
| `hybrid` (по умолчанию) | высокая (~95%) | весь текст | нужен и вид, и правка текста |
| `text` | средняя (шрифты/вёрстка «плывут») | текст + картинки | нужна максимальная редактируемость, вид вторичен |
| `image` | максимальная (1:1) | ничего | скан или нужен только точный вид |

- **Хорошо конвертируются** цифровые PDF, особенно бывшие презентации/слайды:
  извлекается настоящий текст с координатами, шрифтом, размером, цветом.
- **Неизбежно теряется**: точные шрифты (в PDF урезаны/переименованы →
  подстановка сдвигает вёрстку), логическая группировка в абзацы/списки, таблицы
  (только эвристика), векторные диаграммы (в `text` не переносятся; в `hybrid` —
  растровая подложка, не редактируется).
- **Сканы** (PDF без текстового слоя) без предварительного OCR дают пустой текст —
  для них честен только режим `image`. OCR в этот навык не входит.

Полное описание — в `references/conversion-notes.md`. Прочитай его перед выбором
режима и перед ответом пользователю о качестве.

## Перед началом

1. Определи абсолютный путь к каталогу навыка (где лежит `SKILL.md`). Далее —
   `$SKILL_ROOT`.
2. Прочитай `references/conversion-notes.md` полностью.
3. Убедись, что доступны Python 3.11+ и пакеты `pymupdf`, `python-pptx`
   (`pip install pymupdf python-pptx`). Сеть при работе не нужна.

## Обязательный процесс

### 1. Защити вход и задай результаты

- Проверь, что вход существует, имеет расширение `.pdf` и открывается.
- Если пользователь не задал имена, создай рядом `<stem>.pptx` и
  `<stem>_report.md`.
- Вход, результат и отчёт должны разрешаться в три разных пути. Никогда не
  используй входной путь как `--out`.

### 2. Проведи разведку

```bash
python3 "$SKILL_ROOT/scripts/pdf2pptx.py" analyze "$INPUT_PDF"
```

Прочитай весь JSON. Обрати внимание на `recommended_mode`, `scanned_pages`,
разные размеры страниц, повороты и `recommendations`. Если `total_chars` равен 0 —
это скан: предупреди пользователя, что редактируемого текста не будет, и предложи
режим `image` или внешний OCR. Не запускай `convert` вслепую на сканах в режиме
`text`/`hybrid`, обещая редактируемость.

### 3. Выбери режим

- По умолчанию `hybrid` — лучший компромисс.
- `text` — если пользователю важнее всего править содержимое, а точный вид не
  критичен.
- `image` — для сканов или когда нужен ровно вид PDF без правок.

Если запрос неоднозначен, кратко предложи режим и его компромисс, а не молча решай
за пользователя.

### 4. Собери презентацию

```bash
python3 "$SKILL_ROOT/scripts/pdf2pptx.py" convert "$INPUT_PDF" \
  --out "$OUTPUT_PPTX" --report "$REPORT_MD" --mode hybrid --dpi 150
```

Команда публикует PPTX через временный файл (не оставляет полурезультат) и пишет
Markdown-отчёт с посписочными ограничениями. Сохрани JSON из stdout как
доказательство. Код выхода не `0` или `"ok": false` означает, что результат не
готов. Для более чёткой подложки в `hybrid`/`image` подними `--dpi` (например,
200); это увеличивает размер файла.

### 5. Проверь результат независимо

```bash
python3 "$SKILL_ROOT/scripts/pdf2pptx.py" verify "$OUTPUT_PPTX"
```

Готовность подтверждай только когда одновременно:

- `convert` и `verify` завершились с кодом `0` и `"ok": true`;
- число слайдов в `verify` равно числу страниц PDF из `analyze`;
- в режимах `text`/`hybrid` `total_text_chars` близко к `total_chars` из
  `analyze` (расхождение объясни — сканы, повёрнутые страницы, разные размеры);
- PPTX и отчёт существуют и непусты.

### 6. Визуальная проверка, если возможно

Если доступен рендерер PPTX (PowerPoint, LibreOffice Impress, Google Slides или
`soffice --headless --convert-to pdf`), отрендери результат и сверь со страницами
исходного PDF: положение текста, шрифты, наложения, число слайдов. В отчёт допиши
раздел с методом, числом проверенных слайдов и результатом. Если рендерер
недоступен, честно отметь, что визуальная проверка не выполнялась, — не выдавай
структурную проверку за визуальную.

### 7. Заверши ответ

В финальном ответе дай пути к PPTX и отчёту, использованный режим, число слайдов и
редактируемых символов, а также ключевые ограничения (какие элементы не
редактируются, что «поплыло»). Пользователь должен понимать, что именно он
получил.

## Когда остановиться без результата

Остановись и назови конкретную причину, если PDF повреждён/зашифрован без пароля,
`convert`/`verify` вернул ошибку, вход изменился или визуальная проверка выявила
грубое искажение. Для скана в режиме `text`/`hybrid` не заявляй «редактируемую
презентацию» — сообщи, что текст пуст, и предложи `image` или OCR.

## Типичные ошибки

| Ошибка | Правильное действие |
|---|---|
| Обещать «пиксель-в-пиксель И полностью редактируемо» | Объяснить компромисс режимов, выбрать подходящий |
| Гнать скан через `text`/`hybrid` как редактируемый | Определить по `analyze`, предложить `image`/OCR |
| Перезаписать исходный PDF | Всегда отдельный `--out`, три разных пути |
| Считать структурную проверку визуальной | Рендерить слайды, если есть чем; иначе честно отметить пропуск |
| Скрыть потерю векторной графики/таблиц | Перечислить ограничения из отчёта в ответе |
| Собирать PPTX вручную из XML | Использовать только `scripts/pdf2pptx.py` |
