# Аналитика Jira → автономный HTML-дашборд

Навык для кодинг-агента (GigaCode Desktop, Claude Code и совместимых): собирает
из Jira **Server / Data Center** через MCP Atlassian глубокую аналитику работы
команды и оформляет её в один самодостаточный HTML-файл — с графиками, выводами
и предупреждениями.

Агент сам уточняет рамки (проект, период, кого включать, что важнее), тянет
задачи по JQL с историей изменений, а расчёт и рендер выполняет поставляемый
Python-скрипт. Данные не покидают машину: считается всё локально.

## Как участвует ИИ

Скилл сознательно разделяет две роли. **Скрипт считает** — метрики, пороговые
правила, графики: числа воспроизводимы и не зависят от настроения модели.
**Модель анализирует** — читает названия задач, находит повторяющиеся сюжеты,
объясняет причины выбросов и отделяет следствия от корневой проблемы.

Чтобы её выводы были проверяемыми, а не убедительным текстом, есть конвейер:

```
brief → insights.json → validate-insights → render --insights
факты    интерпретация   заземление          публикация
```

`validate-insights` не пропустит ссылку на несуществующую задачу и потребует
доказательств под уверенными утверждениями. Готовый анализ становится **первым
разделом** дашборда, явно отделённым от детерминированных чисел.

## Что внутри дашборда

- **Поток и скорость** — создано против закрытого, пропускная способность,
  накопительная диаграмма потока (CFD), распределение времени цикла с
  перцентилями p50/p75/p85/p95.
- **Люди и нагрузка** — закрытое и незавершённое по исполнителям, медианное
  время цикла, bus factor, доля лидера, задачи без исполнителя.
- **Риски и блокеры** — заблокированные, зависшие в работе (порог — p85
  собственного времени цикла команды), без движения, просроченные, долгожители.
- **Анализ модели** — резюме для руководителя и находки в формате «что видно →
  что это значит → что делать», с уровнем, уверенностью и ссылками на задачи.
- **Где время утекает** — эффективность потока и время по статусам ожидания:
  показывает, что задача «на 574 дня» две трети срока просто ждала ответа.
- **Качество учёта** — пачковые и мгновенные закрытия: сигнал, что метрики
  времени описывают ведение Jira, а не работу команды.
- **Расчётные предупреждения** — детерминированные правила с уровнями от
  `critical` до `good`, каждое с последствиями и задачами-доказательствами.

Файл открывается **без интернета** (ни одной внешней ссылки), работает в светлой
и тёмной теме, графики — инлайновый SVG. Палитра проверена валидатором на
различимость при дальтонизме в обеих темах.

## Требования

- кодинг-агент с настроенным **MCP Atlassian** (нужен инструмент поиска по JQL);
- Python 3.11+ — **без внешних пакетов**, только стандартная библиотека;
- доступ к Jira Server / Data Center с правами на чтение проекта.

## Установка из ZIP

```bash
unzip jira-analytics.zip -d ~/.agents/skills
```

Появится `~/.agents/skills/jira-analytics/` с `SKILL.md`. Вместо `.agents/skills`
используйте каталог навыков вашего агента (например, `~/.gigacode/skills/`).
Перезапустите сессию агента, чтобы он перечитал список навыков.

## Пример вызова

```text
$jira-analytics Проанализируй проект ABC за последние 90 дней. Интересуют
скорость поставки и где затыки. Дашборд положи в /путь/out/.
```

Агент уточнит рамки, выгрузит задачи и вернёт:

- `dashboard.html` — автономный дашборд;
- `metrics.json` — все посчитанные метрики (можно переиспользовать);
- `issues.json` — канонический срез задач;
- выводы словами в самом ответе.

## Проверка без доступа к Jira

Конвейер можно прогнать на синтетических данных в формате Jira DC:

```bash
S=scripts/jira_analytics.py
python3 $S demo      --out raw_demo.json --count 180 --days 120
python3 $S normalize raw_demo.json --out issues.json
python3 $S analyze   issues.json --out metrics.json --granularity week
python3 $S render    metrics.json --out dashboard.html --issues issues.json
python3 -m unittest scripts/test_jira_analytics.py -v
```

## Настройка порогов

```bash
python3 scripts/jira_analytics.py analyze issues.json --out metrics.json \
  --granularity week      `# day | week | month` \
  --since 2026-06-01 --until 2026-09-01 \
  --wip-warn 3            `# сколько задач в работе на человека считать перегрузом` \
  --stale-days 14         `# «без движения»` \
  --longlived-days 90     `# «долгожители»` \
  --story-points-field customfield_10002
```

## Гарантии и ограничения

Скрипт не пишет в Jira — только читает выгрузки с диска. Все числа
воспроизводимы: отчёт собирается из `metrics.json`, а не пересказывается по
памяти. Покрытие историей изменений показывается явно — без `changelog` время
цикла и точный CFD не считаются, и навык говорит об этом, а не подставляет
правдоподобные значения.

Метрики не измеряют качество работы и не учитывают размер задач: число закрытых
задач — это нагрузка и риск концентрации, а не рейтинг сотрудников. Если команда
ведёт статусы неаккуратно, отчёт отразит учёт, а не реальную работу.
