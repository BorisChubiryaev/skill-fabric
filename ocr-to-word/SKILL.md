# Профессиональный офлайн-OCR → редактируемый Word

## Язык общения

Всё общение с пользователем веди **по-русски**: пояснения, статусы, вопросы,
итоговый ответ, комментарии к шагам. Пользователь работает на русском, и
англоязычные вставки в диалоге сбивают. Технические команды, пути и имена флагов,
разумеется, остаются как есть.

## Назначение

Извлекай текст из изображений, сканов PDF и фотографий документов и собирай
редактируемый файл Word (`.docx`). Всё работает **локально** на движке Tesseract —
без сети, API-ключей и загрузки документов куда-либо (это важно для договоров,
паспортов и прочих чувствительных бумаг). Языки по умолчанию — русский и
английский (`rus+eng`).

Главная ценность здесь не «прогнать через OCR», а **не выдать мусор за текст**.
Инструмент оценивает уверенность распознавания по страницам, помечает
подозрительные места и честно сообщает, когда вход слишком плох, — чтобы человек
знал, что перепроверить, а не доверял слепо.

Используй только поставляемый `scripts/ocr_to_word.py`. Не зови `tesseract`
напрямую в обход инструмента и не собирай `.docx` вручную из XML: так теряются
предобработка фото, подсчёт уверенности и защита результата.

## Что реально достижимо (прочитай перед обещаниями)

Tesseract — сильный офлайн-движок, но у него есть границы. Понимание их бережёт
и твоё время, и доверие пользователя:

- **Отлично**: чистые сканы и цифровые изображения печатного текста (рус/англ) —
  уверенность обычно 90%+.
- **Хорошо после предобработки**: фото с телефона — если выровнять перекос,
  увеличить мелкое, подавить шум. Инструмент делает это сам в режиме `auto`.
- **Плохо / не для этого движка**: рукописный текст (Tesseract его практически не
  берёт — честно скажи это и предложи vision-модель как альтернативу вне навыка),
  сильно размытые/пересвеченные фото, декоративные шрифты, текст на фоне графики.
- **Структура**: переносятся абзацы и порядок текста; сложные таблицы и
  многоколоночная вёрстка распознаются приблизительно. Точное форматирование
  оригинала (шрифты, отступы) не воспроизводится — на выходе чистый текст в Word.

Подробности движка, предобработки и типовых проблем — в
`references/ocr-notes.md`. Прочитай перед нестандартным входом.

## Перед началом

1. Определи абсолютный путь к каталогу навыка (где лежит `SKILL.md`) — далее
   `$SKILL_ROOT`.
2. Проверь окружение (движок, языки, пакеты):

   ```bash
   python3 "$SKILL_ROOT/scripts/ocr_to_word.py" check --lang rus+eng
   ```

   Если `ready` не `true`, подними окружение и повтори. Выбор пути зависит от
   того, что доступно на машине, — не ставь всё подряд:

   - **Linux (есть apt/sudo):** `apt-get install tesseract-ocr
     tesseract-ocr-rus tesseract-ocr-eng` + `pip install pytesseract pillow
     numpy opencv-python-headless pymupdf python-docx`.
   - **macOS с Homebrew:** `brew install tesseract tesseract-lang` + те же
     pip-пакеты.
   - **Без sudo и без Homebrew (частый случай на «голом» Mac, в т.ч. GigaCode
     Desktop):** поставь Tesseract из **conda-forge через Miniforge** в домашний
     каталог и запускай скрипт через **uv** — ничего не устанавливая глобально.
     Точные шаги, включая обход блокировки `curl` (скачивание через Python) и
     нужные переменные `PATH`/`TESSDATA_PREFIX`/`UV_DEFAULT_INDEX`, описаны в
     `references/install.md`. Прочитай его целиком перед установкой.

   Скрипт сам ищет бинарь `tesseract` не только на `PATH`, но и в типичных местах
   без sudo (`~/miniforge3/bin`, `~/miniconda3/bin`, `/opt/homebrew/bin`,
   `/usr/local/bin`) и подхватывает соседний `share/tessdata`. Если бинарь лежит
   в нестандартном месте — передай путь флагом `--tesseract-cmd`. Вывод `check`
   в поле `tesseract_cmd` показывает, какой бинарь выбран.

   Не запускай `ocr` вслепую, если `check` не прошёл, — получишь пустой или
   неверный результат.

## Обязательный процесс

### 1. Защити вход и задай результаты

- Проверь, что вход существует и это изображение (`.png/.jpg/.tiff/...`) или
  `.pdf`.
- Если пользователь не задал имена, создай рядом `<stem>.docx` и
  `<stem>_ocr_report.md`.
- Вход, результат и отчёт должны разрешаться в разные пути. Никогда не используй
  входной путь как `--out`.

### 2. Выбери язык и режим предобработки

- Языки: по умолчанию `--lang rus+eng`. Для другого набора задай явно (нужен
  соответствующий языковой пакет Tesseract).
- Предобработка (`--preprocess`):
  - `auto` (по умолчанию) — сам определит перекос и уровень шума. Подходит для
    большинства входов, включая фото.
  - `scan` — чистые сканы/PDF (серый + выравнивание перекоса, без лишнего).
  - `photo` — форсировать «фото-конвейер» (шумоподавление + выравнивание
    освещённости), если `auto` недооценил плохое качество.
  - `none` — без обработки, только серый (когда изображение уже идеально
    подготовлено и любая обработка мешает).

Не применяй жёсткую бинаризацию «на всякий случай»: Tesseract сам бинаризует
хорошо, а лишняя обработка чаще разрушает текст, чем помогает. Именно поэтому
инструмент по умолчанию действует консервативно.

### 3. Распознай и собери DOCX

```bash
python3 "$SKILL_ROOT/scripts/ocr_to_word.py" ocr "$INPUT" \
  --out "$OUTPUT_DOCX" --report "$REPORT_MD" --lang rus+eng --preprocess auto
```

Добавь `--json "$OUT_JSON"`, если нужны слова с координатами и уверенностью
(bounding boxes) для дальнейшей обработки. Инструмент публикует `.docx` через
временный файл (не оставляет полурезультат), помечает красным ненадёжные абзацы
и пишет отчёт с уверенностью по страницам. Сохрани JSON из stdout как
доказательство. Код выхода не `0` или `"ok": false` означает, что результата нет
(например, `total_words` = 0 — текст не распознан).

### 4. Оцени качество по отчёту

Прочитай `overall_confidence` и `low_confidence_pages` из вывода и таблицу в
отчёте. Трактуй так:

- уверенность **90%+** — обычно чистый результат, беглая сверка;
- **60–90%** — приемлемо, но перепроверь помеченные красным места;
- **ниже 60%** — вход плохой: не выдавай это за готовый текст. Предложи
  конкретно улучшить вход (снять ровно, без бликов, крупнее, выше DPI) и
  повторить, либо, для рукописного/сложного входа, применить vision-модель вне
  этого навыка.

### 5. Заверши ответ

Дай пути к `.docx` и отчёту, языки, число страниц и слов, общую уверенность и
список ненадёжных страниц. Если качество низкое или встретилась рукопись —
скажи об этом прямо, а не отдавай сомнительный текст молча.

## Когда остановиться без результата

Остановись и назови причину, если `check` не прошёл, вход повреждён/пустой,
`ocr` вернул `total_words` = 0 или общая уверенность настолько низка, что текст
недостоверен. Для рукописного ввода честно сообщи, что Tesseract для него не
предназначен.

## Типичные ошибки

| Ошибка | Правильное действие |
|---|---|
| Обещать распознавание рукописи через Tesseract | Сказать о границе движка, предложить vision-модель |
| Отдать текст с уверенностью 30% как готовый | Показать уверенность, предложить улучшить вход и повторить |
| Жёстко бинаризовать любой вход | Довериться `auto`; сильная обработка ломает чистый текст |
| Перекошенное фото → 0 слов | Использовать `auto`/`photo`: инструмент выровняет перекос |
| Перезаписать исходный файл | Всегда отдельный `--out`, разные пути |
| Звать `tesseract` напрямую / клеить DOCX из XML | Использовать только `scripts/ocr_to_word.py` |
