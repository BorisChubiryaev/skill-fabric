# Движок, предобработка и типовые проблемы OCR

Справочник для агента. Прочитай перед нестандартным входом или когда качество
распознавания оказалось низким.

## Движок

- Используется **Tesseract** (`--oem 3`, LSTM) через `pytesseract`, офлайн.
- Языки задаются пакетами traineddata (`rus`, `eng`, …). Проверить установленные:
  `tesseract --list-langs`. Доустановить: `apt-get install tesseract-ocr-<lang>`.
- Для нескольких языков в одном документе передавай их через `+`: `rus+eng`.
  Лишние языки слегка замедляют и иногда путают движок — не добавляй языки,
  которых в документе нет.

## Как инструмент читает вход

- **Изображения** (`png/jpg/tiff/bmp/webp/gif`) — открываются напрямую.
- **PDF** — каждая страница рендерится в растр через PyMuPDF при `--pdf-dpi`
  (по умолчанию 300). Это работает и для сканов без текстового слоя. 300 DPI —
  хороший баланс качества и скорости; для мелкого шрифта подними до 400.
- Многостраничный вход → каждая страница становится отдельной страницей в DOCX
  (разрыв страницы между ними).

## Предобработка (почему она консервативная)

Главный принцип: **помогать движку, а не мешать**. Tesseract сам выполняет
качественную бинаризацию (Otsu/адаптивную) внутри. Внешняя жёсткая бинаризация,
особенно адаптивная с агрессивными параметрами, часто разрушает тонкие штрихи
букв и превращает текст в шум — на практике это давало 0 распознанных слов на
изображении, которое в градациях серого читалось на 95%.

Поэтому конвейер по умолчанию (`auto`) ограничивается тем, что почти всегда
помогает:

1. **Градации серого.**
2. **Выравнивание перекоса (deskew).** Угол оценивается по `cv2.minAreaRect`
   облака тёмных пикселей. Знак коррекции: `-(90+angle)` при `angle < -45`, иначе
   `-angle` (частая ошибка — перепутать знак и удвоить перекос). Углы > 20°
   игнорируются как ошибочная оценка. Это самый надёжный выигрыш для сканов и
   фото.
3. **Апскейл мелких изображений.** Если большая сторона < 1000 px, увеличиваем
   ×2: Tesseract любит высоту строчных букв ~30+ px (≈300 dpi).
4. **Только для фото** (или когда оценка шума высока): щадящее `fastNlMeansDenoising`
   + `CLAHE` для выравнивания неравномерной освещённости. Без жёстких порогов.

Режимы:

- `auto` — оценивает перекос и шум (разброс лапласиана) и выбирает обработку.
- `scan` — серый + deskew + апскейл (без шумоподавления).
- `photo` — форсирует фото-ветку (шум + CLAHE), если `auto` недооценил.
- `none` — только серый; для уже идеально подготовленных изображений.

Если результат плох, пробуй в таком порядке: другой `--preprocess`, выше
`--pdf-dpi`, другой `--psm`.

## Режимы сегментации (`--psm`)

- `3` (по умолчанию) — полная авторазметка страницы. Подходит большинству.
- `6` — «один однородный блок текста»: помогает на простых сканах без колонок.
- `4` — «одна колонка текста разной высоты».
- `11`/`12` — разреженный текст (таблички, подписи), когда `3` теряет строки.

## Уверенность и её трактовка

Tesseract возвращает уверенность по каждому слову (0–100). Инструмент усредняет
её по странице и по документу.

- **90%+** — обычно чистый результат.
- **60–90%** — приемлемо; проверь помеченные красным (в DOCX) фрагменты.
- **< 60%** — вход плохой; не выдавай за готовый текст.

Важно: высокая уверенность — не гарантия правильности (движок бывает «уверенно
неправ»), но низкая уверенность — надёжный сигнал проблемы. Красная пометка
абзацев в DOCX помогает человеку быстро найти, что перепроверить.

## Границы и честные альтернативы

- **Рукописный текст.** Tesseract на него практически не рассчитан. Не пытайся
  «дожать» параметрами — честно сообщи и предложи vision-модель (Claude/GigaChat
  Vision) или специализированный HWR-сервис вне этого навыка.
- **Таблицы.** Распознаётся текст ячеек как абзацы, но не структура таблицы.
  Для табличных данных лучше отдельный layout-инструмент.
- **Форматирование.** На выходе — чистый редактируемый текст в Word, без
  воспроизведения шрифтов/отступов оригинала. Если нужен точный вид, это другая
  задача (например, searchable PDF поверх оригинала).
- **Низкое разрешение / блики / перекос > 20°.** Улучшай вход на стороне съёмки:
  ровный кадр, равномерный свет, крупнее, выше DPI — это даёт больший прирост,
  чем любые параметры OCR.
